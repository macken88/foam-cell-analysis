1.1 GUI 側の約束事

  • すべての画面（ページ）は BasePage(QWidget) を継承し、__init__(self, ctx: AppContext, parent=None) と on_enter(self, params: dict) -> None を持つ。
  • ページは表示されるたびに on_enter で backend から最新データを読み直す（画面間の整合はこれで取る）。
  • 画面遷移は必ず ctx.navigator.navigate(PageId.X, **params) を使う。ページ同士が直接参照し合わない。
  • ダイアログは各モードの dialogs.py などに置き、モーダル（exec()）とする。ただし、データ拡張プロファイル編集は大きめのダイアログにする。
  • 長い処理（取り込み、整合性確認、アーカイブ、学習、評価、マスク出力、推論）は FakeJob で進捗を模擬する。
  • 画面遷移してもジョブは継続する（JobManager が保持）。
  • 実行中ジョブ数をステータスバーに表示する。
  • 確定済みのもの（データセット版、実験で使用済みのデータ拡張プロファイル、リリース済みモデル）は、GUI 上でも編集不可（読み取り専用表示）にする。
  • 破壊的または取り消せない操作（データセット確定、リリース登録、振り分けの適用、学習の中断）は確認ダイアログを出す。
  • 文言は日本語。内部キーは必要に応じてツールチップや YAML プレビューで表示する。

2. アプリ全体の画面構成

v1 は左のサイドバーでページを切り替える1ウィンドウ構成だった。v2 では、サイドバーのぶん作業エリアが狭くなるのを避けるため、ホームウィンドウから各モードを選び、モードごとの専用ウィンドウを開く構成に変える。

2.6 見た目の設計（全画面共通）v2.5

このアプリで一日の大半を占めるのは、数百〜数千枚の画像を見て用途・分類・品質を決める作業と、学習・評価の数字を見比べる作業である。見た目はこの2つを速く、間違えずに行えることを優先し、装飾で作業エリアを狭めない。本書の画面モックはすべてこの節の見た目で描いている（ブラウザ上の近似であり、Qt での実際の表示とは細部が異なる）。

2.6.1 方針

  1. 色はデータの意味にだけ使う。作業エリアで色が付いているものは、必ず用途（学習・検証・未振り分け・不採用）、エラー、変更ありのどれかを表す。ボタン・選択行・タブ・フォーカスは無彩色（グラファイトと灰）で表す。これで学習の青や検証の橙が、ボタンの色と混ざらない。
  2. 数字は計測値の書体で表示する。件数・mAP・エポック・版番号・時刻・データ識別子は Bahnschrift の等幅数字にし、縦にそろえて読み比べられるようにする。
  3. 画像がいちばん目立つ。画像の背景は暗い灰色とし、周りの UI は明るく控えめにする。原画像やマスクの色と競う色を UI に使わない。
  4. 目立たせるのはホームの工程の流れ（2.1）だけ。モードウィンドウは影付きのカードや角丸の枠を使わず、罫線1本で区切る。動きはホームの学習中の点の明滅だけとする。

2.6.5 実装への影響

  • gui/theme.py を追加する。
    • 色とフォントを定数で持ち（Color.TRAIN、Font.NUMERIC など）、build_stylesheet() でアプリ全体のスタイルシートを作る。app.py の apply_style はこれを呼ぶだけにする。
    • フォントが見つからない場合の代わり（BIZ UDPゴシック → Yu Gothic UI、Bahnschrift → Segoe UI）を QFontDatabase で確かめて選ぶ。
  • ページ内で直接 setStyleSheet で色を書くのをやめ、動的プロパティで名前付きのスタイルを指定する: role="note"（補足文）、role="readonly"、role="numeric"、state="ok" | "error" | "changed"、usage="train" | "val" | "unassigned" | "excluded"。
  • gui/widgets/marks.py に用途タグ・件数チップ・原画像切替トグルの共通部品を置く。表のセルの用途タグと状態タグは QStyledItemDelegate で描く。
  • 表のモデルは、用途・状態・変更ありを Qt.UserRole 系のデータで返し、色はデリゲートとテーマが決める（モデルに色を持たせない）。
  • テスト: 主な画面で直接の色指定が残っていないこと（setStyleSheet の検索）、用途ごとのタグの文字が正しいことを確かめる。見た目の最終確認は、各画面のスクリーンショットを撮って行う。

3. 共通部品

3.1 FakeJob / JobManager（gui/jobs.py）

  • FakeJob(QObject): name, total_steps, interval_ms を持つ。シグナルは progress(int step, int total, str message), finished(bool ok, str message)。
  • 1ステップごとに on_step(step) コールバックを呼ぶ。backend の状態更新に使う。
  • cancel() あり。
  • JobManager(QObject): ジョブを保持し、jobs_changed シグナルでステータスバーの件数を更新する。
  • 速度係数: 環境変数 FOAM_MOCK_SPEED（既定 1.0）で interval_ms を割る。テストでは大きな値にして高速化する。
  • 進捗表示: JobProgressDialog（ページ内でジョブを開始し、進捗を見せたい場合に使う。キャンセルボタン付き・非モーダル可）。

3.2 画像表示（gui/widgets/image_view.py, image_convert.py）

  • ImageView(QGraphicsView): ホイールでズーム、ドラッグでパン、ダブルクリックで全体表示。
  • ViewSynchronizer: 複数の ImageView のズーム倍率とスクロール位置を同期する（マスク比較で使用）。
  • 描画形式 DisplayMode は IMAGE（原画像）, OVERLAY, INSTANCE_LABEL, BINARY を持つ。画面設定はこのうち1種類を保存し、利用者は原画像と設定表示を二択で切り替える。既定はオーバーレイ。
  • to_binary_separated(labels): 仕様どおり、異なるインスタンス同士の8近傍接触ピクセルを背景化した二値マスクを返す。モックだが numpy で実装してよい（処理は軽い）。
  • 画像が無い場合は「画像なし」の灰色プレースホルダを表示する。

3.3 フォーム（gui/widgets/form.py）

  • FormSection(QGroupBox): タイトル付き、add_row(label, widget, tooltip=内部キー)。
  • CollapsibleSection: 「詳細設定 ▶/▼」で開閉（Mask R-CNN の RPN/ROI 設定に使う）。
  • 数値は QSpinBox / QDoubleSpinBox。学習率など桁が小さいものは指数表記を許す QLineEdit + バリデータでもよい。

3.4 学習曲線（gui/widgets/chart.py）

  • QtCharts は使わず、QPainter で折れ線を描く簡易ウィジェット。系列（名前・色・点列）を複数重ねられる。
  • 実験比較で複数実験の mAP 曲線を重ねるのに使う。

4. データ準備（PageId.DATA_PREPARATION）

仕様: データ準備モード仕様 全章。数百〜数千枚の画像をフォルダ単位で取り込んで振り分ける作業を前提に、v1 の画面を見直した構成（v2）。v2.2 までのレビューの回答と要望を反映し、実装済み。

改良の方針
  1. 用途は画面の切り替えではなく「列」で持つ。1つの作業表で「未振り分け／学習／検証／不採用」を扱い、学習用・検証用のモード切り替えをなくす。
  2. 取り込み時にフォルダ単位で値をそろえる。
    • 取り込むフォルダを選ぶと、ポップアップで「フォルダ内で統一する項目（列）」を選び、フォルダごとに値を入れる。
    • 入れた値は、各画像のメタデータとして書き込む。フォルダ自体のメタデータは保持しない。
    • 取り込んだ後は、すべて画像ごとの値として扱う。
  3. 人が1枚ずつ判断する作業だけを残す。
    • 自動で決まるもの: マスクの対応、整合性確認
    • フォルダ単位・一括で決めるもの: 取り込み時の統一項目（分類など）、学習/検証の分割
    • 目で見て決めるもの: 例外的な品質、不採用
  4. 操作方法を3通り用意する。どの操作もキーボード、表のコンボボックス、Excel での一括編集のいずれでも行える。キーの割り当ては利用者が変更できる。
  5. 画面上のボタンを減らす。整合性確認は自動で行い、手動の確認ボタンと VALIDATED の手順は廃止する。

4.2 作業の流れの比較（5フォルダ・500枚を追加して新しい版を作る例）

v1
  1. 対象を「学習用」に切り替える
  2. 取り込み（全件に同じ分類）
  3. 分類をコンボで直す（多数の行）
  4. 品質をコンボで設定する（多数の行）
  5. 検証に回す画像を別の手順で取り込み直す
  6. 整合性確認 → エラー修正 → 再確認
  7. 学習用を確定
  8. 対象を「検証用」に切り替え、手順 4〜7 を繰り返す

クリック数の目安: 1,000回以上（1枚あたり分類と品質でそれぞれ2クリック）

v2
  1. 5つのフォルダをまとめて画面にドラッグ → ポップアップで統一する項目（例: 画像分類・品質）にチェックを入れ、フォルダごとに値を選ぶ（5行ぶん）
  2. Ctrl+D 自動振り分け（検証 20%、分類ごとに層化）
  3. 表のプレビューは「原画像」と設定した1種類の表示を切り替える。GUI は最初のチャンネルを使う。例外の画像だけ品質を変えるか不採用にする。
  4. ⚠ が付いた行だけを直す（自動検査）
  5. Ctrl+Enter で確定（train/val をまとめて発行）

  • 表（左）: 上部に「全件数 件中 表示件数 件を表示」と「表示する列 ▾」を置く。既定列は状態の印・元ファイル名・用途・画像分類・品質。識別子・取り込み元フォルダ・マスク版は任意表示とし、表示状態を設定へ保存する。
  • プレビュー（右）: 選択中の元ファイル名を大きく表示し、下に識別子・取り込み元・マスク版を小さく表示する。原画像と設定表示を二択で切り替える。一括変更コンボは「選択中の N 件を変更」の枠にまとめ、狭い幅では 2 行に折り返す。表または画像プレビューを操作中は現在行・スクロール位置を保ち、入力部品にフォーカスがある間は表操作用の編集ショートカットを実行しない。
  • 表の列幅: 幅は設定に保存し、列の表示・非表示と組み合わせて次回復元する。古い列幅設定は無視し、既定幅で表示する。ファイル名列を伸ばして余白を抑える。

4.6 用途の規則

  • 新しく取り込んだデータは、取り込み時に用途を統一しなければ「未振り分け」になる。未振り分けが残っていても確定できる（その行は版に含めず、確定ダイアログで件数を知らせる）。作業を何回かに分けられる。
  • 用途の変更に制限は設けない。検証から学習、学習から検証への移動も、禁止や警告をせずにそのまま行える（データリークは運用で管理する — 4.16 の決定事項 1）。
  • 品質と用途は別の概念のままとする（仕様 2.3）。品質が「不良」でも学習・検証に入れられる。
  • 学習用版が参照する「基準検証用データセット」は、確定時に同時に発行した val 版（val に変更がなければ最新の val 版）を自動で紐付ける。
