# GUI 画面設計書（モック実装版）

対象: `docs/specs/` の仕様書4本に記載された全画面。
目的: バックグラウンド処理はモックとし、画面・操作・画面遷移を先に確認できる状態にする。

- GUI: PySide6（Qt Widgets）。QML は使わない。
- 画面表示は日本語。設定の内部キーは英語（仕様書 14章）。
- 画面処理（`gui/`）とデータ・処理（`services/`）を分離する。GUI は `Backend` 経由でのみデータにアクセスする。
- Python 3.12。依存は pyproject.toml の基本依存（PySide6, numpy, pandas, openpyxl, Pillow, tifffile, PyYAML）のみ。torch 等は使わない。

### 1.1 GUI 側の約束事

- すべての画面（ページ）は `BasePage(QWidget)` を継承し、`__init__(self, ctx: AppContext, parent=None)` と `on_enter(self, params: dict) -> None` を持つ。
- ページは表示されるたびに `on_enter` で backend から最新データを読み直す（画面間の整合はこれで取る）。
- 画面遷移は必ず `ctx.navigator.navigate(PageId.X, **params)` を使う。ページ同士が直接参照し合わない。
- ダイアログは各モードの `dialogs.py` などに置き、モーダル（`exec()`）とする。ただし、データ拡張プロファイル編集は大きめのダイアログにする。
- 長い処理（取り込み、整合性確認、アーカイブ、学習、評価、マスク出力、推論）は `FakeJob` で進捗を模擬する。
  - 画面遷移してもジョブは継続する（`JobManager` が保持）。
  - 実行中ジョブ数をステータスバーに表示する。
- 確定済みのもの（データセット版、実験で使用済みのデータ拡張プロファイル、リリース済みモデル）は、GUI 上でも編集不可（読み取り専用表示）にする。
- 破壊的または取り消せない操作（データセット確定、リリース登録、振り分けの適用、学習の中断）は確認ダイアログを出す。
- 文言は日本語。内部キーは必要に応じてツールチップや YAML プレビューで表示する。

## 3. 共通部品

### 3.1 FakeJob / JobManager（`gui/jobs.py`）

- `FakeJob(QObject)`: `name`, `total_steps`, `interval_ms` を持つ。シグナルは `progress(int step, int total, str message)`, `finished(bool ok, str message)`。
  - 1ステップごとに `on_step(step)` コールバックを呼ぶ。backend の状態更新に使う。
  - `cancel()` あり。
- `JobManager(QObject)`: ジョブを保持し、`jobs_changed` シグナルでステータスバーの件数を更新する。
- 速度係数: 環境変数 `FOAM_MOCK_SPEED`（既定 1.0）で `interval_ms` を割る。テストでは大きな値にして高速化する。
- 進捗表示: `JobProgressDialog`（ページ内でジョブを開始し、進捗を見せたい場合に使う。キャンセルボタン付き・非モーダル可）。

### 3.2 画像表示（`gui/widgets/image_view.py`, `image_convert.py`）

- `ImageView(QGraphicsView)`: ホイールでズーム、ドラッグでパン、ダブルクリックで全体表示。
- `ViewSynchronizer`: 複数の `ImageView` のズーム倍率とスクロール位置を同期する（マスク比較で使用）。
- 表示形式 `DisplayMode`: `IMAGE`（原画像）, `OVERLAY`（原画像 + インスタンスを色付き半透明で重ね、輪郭線）, `INSTANCE_LABEL`（インスタンスごとに色分けしたラベル画像）, `BINARY`（粒子解析用二値マスク）。
- `to_binary_separated(labels)`: 仕様どおり、異なるインスタンス同士の8近傍接触ピクセルを背景化した二値マスクを返す。モックだが numpy で実装してよい（処理は軽い）。
- 画像が無い場合は「画像なし」の灰色プレースホルダを表示する。

### 3.3 フォーム（`gui/widgets/form.py`）

- `FormSection(QGroupBox)`: タイトル付き、`add_row(label, widget, tooltip=内部キー)`。
- `CollapsibleSection`: 「詳細設定 ▶/▼」で開閉（Mask R-CNN の RPN/ROI 設定に使う）。
- 数値は `QSpinBox` / `QDoubleSpinBox`。学習率など桁が小さいものは指数表記を許す `QLineEdit` + バリデータでもよい。

### 3.4 学習曲線（`gui/widgets/chart.py`）

- QtCharts は使わず、`QPainter` で折れ線を描く簡易ウィジェット。系列（名前・色・点列）を複数重ねられる。
- 実験比較で複数実験の mAP 曲線を重ねるのに使う。

## 4. データ準備（`PageId.DATA_PREPARATION`）

仕様: データ準備モード仕様 全章。

### 4.1 レイアウト

```
[対象: (学習用 ▼ / 検証用)]   状態: WORKING   自動保存済み 12:03:10
┌ 現在の作業中データセット ─────────────────────────────────────┐
│ ベース版: train_v003  登録画像数: 537  マスク数: 537            │
│ 未入力メタデータ: 12  整合性エラー: 0  追加 +23 除外 -2 変更 14   │
│ [データ取り込み…] [Excel出力…] [Excel取込…] [整合性確認を実行]   │
│                                             [データセットを確定…]│
└──────────────────────────────────────────────────────────────┘
┌ タブ: [作業中データ] [整合性確認] [データセット版履歴] ───────────┐
```

- 対象（学習用 / 検証用）を切り替えると、それぞれの作業中データセットに切り替わる。学習用のベース版は `train_vNNN`、検証用は `val_vNNN`。
- 状態は `WORKING` / `VALIDATED`（仕様 7.1）。整合性確認に成功すると `VALIDATED`。その後に何か編集すると `WORKING` に戻る。
- 「データセットを確定…」は `VALIDATED` のときだけ有効。
- 編集のたびに backend へ即時保存し（自動保存）、「自動保存済み HH:MM:SS」を更新する。手動保存ボタンは置かない。

### 4.2 タブ「作業中データ」

左に表、右にプレビューを置く（`QSplitter`）。

表の列:

| 列 | 編集 | 備考 |
|---|---|---|
| 採用 | チェックボックス | 外すと「除外」。保管領域からは削除しない |
| データ識別子 | 不可 | item_000001 |
| 元ファイル名 | 不可 | |
| 画像分類 | コンボ（分類A/分類B/分類C/未設定） | 表記揺れ防止のため選択式 |
| 品質 | コンボ（良/可/不良/未設定） | 採用とは別概念 |
| チャンネル | 不可 | A, B, C |
| マスク版 | コンボ（rev_001, rev_002…） | そのデータに存在する版のみ |
| 変更 | 不可 | 追加 / 変更 / 除外 / — |
| 検証 | 不可 | エラーがあれば ⚠ と件数 |

- 表の上に絞り込み: 画像分類、品質、「変更ありのみ」、「エラーありのみ」、テキスト検索（データ識別子・ファイル名）。
- 複数行を選択して「選択を除外」「選択を採用に戻す」「画像分類を一括設定」「品質を一括設定」ができる。
- 右プレビュー: `ImageView` + チャンネル選択（A/B/C）+ 表示形式（原画像/オーバーレイ/インスタンスラベル）+ マスク版表示 + そのデータのハッシュ（SHA-256 先頭16桁）・元の相対パス。
- 「新しいマスク版を取り込む…」ボタン（選択データ1件）: マスクファイル選択 → rev を1つ増やした版を追加（上書きしない）。

### 4.3 タブ「整合性確認」

- 仕様 7章の8項目をチェックリストで表示し、各項目に 未実行 / OK / NG（件数）を出す。
- 下にエラー表（重要度、データ識別子、検査項目、内容）。行をダブルクリックすると「作業中データ」タブで該当行を選択する。
- 「整合性確認を実行」は FakeJob（数秒）。モックのルール: 画像分類または品質が「未設定」の採用データを「必須メタデータ未入力」エラーとする。それ以外は OK。
  → 未設定をすべて埋めると VALIDATED にできる。シードデータには未設定を数件含める。

### 4.4 タブ「データセット版履歴」

- 表: 版、用途、親版、作成日時、画像数、状態（RELEASED）、アーカイブ状態（NOT_CREATED / COMPLETED / FAILED）、コメント。
- 選択した版の詳細（読み取り専用）: 仕様 6.3 の項目 + 学習用なら基準検証用データセット。
- 「アーカイブ作成…」: 出力先フォルダ選択 → FakeJob → 結果（zip 名、SHA-256）。
  - モック: 出力先パスに `fail` を含むと FAILED になる（失敗表示の確認用）。FAILED でも版は RELEASED のまま。再実行できる。
  - 実ファイルは作らない。
- 確定済みの版は編集手段を一切出さない。

### 4.5 ダイアログ

**データ取り込み**
- 画像フォルダ（チャンネルごとに A/B/C のフォルダ、A 必須）、マスクフォルダ、画像分類の初期値。
- 「検索」で見つかった組の一覧（モック: フォルダ名に関係なく 5〜10 件の架空ファイルを返す）。
- 取り込み → FakeJob → 作業中データに「追加」として並ぶ。

**Excel出力**
- 保存先選択 → 「出力しました（モック）」表示。実ファイルは作らない。

**Excel取込**
- ファイル選択 → 取込前チェック（必須列、識別子重複、未知識別子、型、許容値、空欄）の結果を表示。
- モック: ファイル名に `error` を含むとエラー一覧を出して中断（取り込まない）。それ以外は「変更予定 N 件」のプレビュー表（データ識別子、列、変更前 → 変更後）を出し、「取り込む」で反映する。

**データセットを確定**（仕様 11章）
```
新しいデータセットを作成
用途      : 学習用
版        : train_v004
親版      : train_v003
画像数    : 537      追加 +23  除外 -2  変更 14
基準検証用データセット: [val_v003 ▼]   （学習用のみ）
重複チェック: 検証用データセットとの重複 0 件  ✔
コメント  : [                    ]
                              [キャンセル] [train_v004 を作成]
```
- 学習用の場合、基準検証用データセットとの重複（データ識別子・ハッシュ）を表示する。重複が1件以上あれば作成ボタンを無効にし、重複データを一覧表示する。モックでは重複 0 件。
- 作成後: 履歴に新しい版を追加し、作業中データセットのベースを新しい版に更新、状態を WORKING に戻す。
- 続けて「アーカイブを作成しますか？」を聞く（はい → アーカイブ作成ダイアログ）。

## 5. モデル学習（`PageId.TRAINING`）

仕様: モデル学習モード仕様 3〜7章、9〜10章、14章。

### 5.1 レイアウト

左にフォーム（`QScrollArea`）、右に「設定プレビュー（YAML）」を置く（`QSplitter` 7:3）。
右は仕様 15章の形式の YAML を読み取り専用で表示し、フォームの変更に即時追従する。これで日本語表示と英語内部キーの対応を確認できる。

フォームのセクション（上から）:

1. **実験**: 実験群（編集可能コンボ。既存の実験群 + 新規入力）、実験識別子（自動採番・読み取り専用、例 exp_0045）、説明。
2. **データセット**
   - データセット版: 学習用の確定済み版のみ（train_v001…）。
   - 交差検証分割: split_001…（「正式評価用の検証用データセットとは別」を注記）。
   - 画像分類: 全分類 / 分類A / 分類B / 分類C。
   - 品質条件: すべて / 良のみ / 良・可。
   - 入力チャンネル: チャンネルA/B/C のチェックボックス。
   - 乱数シード。
   - 見込み使用データ数（ラベル）: 「学習 412 件 / 学習内検証 103 件」。条件変更で再計算する（モック計算でよい）。
3. **モデル**: モデル種類（Mask R-CNN / Cellpose）。選択に応じて下の固有設定を `QStackedWidget` で切り替える。
   - Mask R-CNN（仕様 14.2）: 事前学習済み重み、バックボーン、学習するバックボーン層数、入力画像の短辺サイズ、入力画像の最大辺サイズ、画像平均・標準偏差。
     折りたたみ「詳細設定」に RPN（アンカーサイズ、アンカー縦横比、RPN前景/背景IoU閾値、RPNバッチ数/画像、RPN正例割合、RPN NMS閾値、pre/post NMS top N）と ROI（Box前景/背景IoU閾値、ROIバッチ数/画像、ROI正例割合）。
   - Cellpose（仕様 14.3）: 事前学習済みモデル、最適化手法、正規化、スケール変動幅、リスケール、学習パッチサイズ、1エポック当たり画像数、最小マスク数、クラス重み。
     注記: 「セル確率閾値・フロー閾値はこの画面ではなく、モデル比較・リリースの推論設定で管理します」。
4. **共通学習設定**: エポック数、バッチサイズ、学習率、重み減衰、早期終了（有効/無効 + 待機エポック数）。
5. **データ拡張**: プロファイル（コンボ）、[プレビュー] [表示 / 編集…]。どちらもデータ拡張プロファイル編集ダイアログを開く（プレビューはプレビュー部分を強調するだけでよい）。
6. **途中保存モデル / 評価**: 保存間隔（エポック）、最終モデルを保存、最良モデルを保存、最良モデル判定指標（インスタンス平均適合率(mAP) 固定表示に近いコンボ）、判定方向（最大化 / 最小化）、検証間隔。

各入力の `toolTip` に内部キーを設定する（例 `learning_rate`）。

下部ボタン: [設定を検証] [下書き保存] [学習開始]
- 設定を検証: 結果ダイアログに OK/警告/エラーを一覧表示する。モックのルール例: バッチサイズ > 16 で警告（GPUメモリ）、入力チャンネル未選択でエラー、データセット版未選択でエラー、同一設定の実験がすでにあれば「同一設定の実験 exp_xxxx があります」と警告。
- 下書き保存: 実験一覧に状態「下書き」で追加（または更新）する。
- 学習開始: 検証でエラーがあれば開始しない。確認ダイアログの後、実験を「実行中」で登録し、FakeJob で学習を模擬して、実験一覧へ遷移（`select=exp_id`）。
  - 学習の模擬: エポックが進むごとに loss/mAP を生成し、保存間隔ごとに epoch_NNN.pt、最良更新時に best.pt、終了時に last.pt を追加する。既定の速度で 20 秒程度で完了する。
- `on_enter(copy_from=exp_id)` のときは、その実験の設定をフォームへ読み込み、新しい実験識別子を採番する。

- `make_sample(seed, size=512, channels=("A",)) -> (dict[channel, uint8 HxW], labels int32 HxW)`: 背景ノイズ + 明るい縁と暗い中心を持つ円形の気泡を 20〜60 個描く。一部は接触させる（二値分離の確認用）。
- `predict_like(labels, seed) -> labels`: 正解ラベルから一部を欠落・膨張・収縮させた「予測結果」を作る（候補ごとの違いを見せる）。
- 同じ seed なら同じ画像になること。生成結果はキャッシュする。
