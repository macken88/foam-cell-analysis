気泡 インスタンスセグメンテーションアプリ
モデル学習モード仕様・画面モック

本仕様は、気泡検出用インスタンスセグメンテーションモデルの学習、交差検証（OOF）評価、保存を行う管理者向け「モデル学習モード」を対象とする。正式なモデル比較とリリースは別モードで行う。

初期対応モデル：Cellpose / マスク R-CNN
初期前提：推論時のアンサンブルは行わず、リリース済みモデルを1つ選択して推論する。

1. 基本方針

  • 複数モデルに対応できる構造とするが、初期実装はCellposeとマスク R-CNNの2モデルに限定する。
  • モデル差分を無理に共通化せず、「共通ワークフロー + モデルアダプタ」で吸収する。
  • データセット、実験、途中保存モデル、評価、保存は共通化する。
  • モデル構築、モデル固有前処理、損失、RPN/ROI設定、Cellpose固有スケール処理等は各アダプタ側に保持する。
  • 1つでも論理的な学習設定が異なる場合は別実験とする。
  • 同一学習中の途中途中保存モデルは同じ実験に属する。
  • 正式な推論対象の決定は本モードでは行わず、実験と途中保存モデルをモデル比較・リリース段階へ引き渡す。
GPU機種、num_workers、保存先など結果の意味を直接変えない実行環境差は、原則として実験設定ではなく実行試行側の情報として記録する。

2.1 Optunaとの対応

Optuna利用時は、各試行を通常の実験と同じ保存形式で扱う。Optuna専用の結果形式を別途作らず、一つの実験群が複数実験を自動生成する構造とする。

Optunaによる実験群 ├─ 試行 0 → 実験 101 ├─ 試行 1 → 実験 102 ├─ 試行 2 → 実験 103 └─ ...

7. 交差検証（OOF）・チェックポイント

7.1 フォールドごとの学習

各フォールドを順に検証側として学習し、検証間隔ごとにフォールド別mAPを記録する。各エポックのOOF mAPは全フォールドの検証予測を集約して求める。早期終了はフォールドごとに適用し、OOF曲線は全フォールドが到達した最後のエポックまでとする。

7.2 共通エポックの選択と最終学習

OOF mAPが最大となる1つのエポックを選択し、全フォールド共通で使う。選択エポック時点のOOF予測を保存する。その後、学習用データ全体を選択エポック数まで再学習してfinal.ptを必ず保存する。最終学習には検証部分がないためlossのみ記録する。

  • save_every: フォールドごとの定期保存間隔。
  • validation_interval: 各フォールドの検証間隔。
  • best_metric: OOF mAP（oof_instance_map）を最大化して選択エポックを決める。
  • save_fold_models: フォールドごとのモデル保存を有効にする設定。
checkpoints/
├─ fold_1/epoch_010.pt
├─ fold_1/selected.pt
├─ ...
└─ final.pt

評価値はOOF mAPを全体・画像分類別に保持し、対象件数も保存する。検証用データセットの評価はモデル比較段階で別に行う。

8. モデル比較・リリース段階への引き渡し

管理者は途中保存モデルを直接本番推論へ割り当てない。本モードでは実験と途中保存モデルまでを確定し、推論設定の比較、検証用データセットでの正式評価、リリース済みモデルの登録、画像分類ごとのモデル振り分けは「モデル比較・リリース」モードで行う。

実験 ↓ 途中保存モデル ↓ モデル比較・リリース ↓ 比較候補作成 ↓ 正式評価 ↓ リリース済みモデル

チャンネルドロップchannel_dropout複数チャンネルの一部を意図的に弱める、または無効化する変換。
適用順序pipeline_order複数のデータ拡張をどの順番で適用するかを定義する。

16. 現時点の設計原則まとめ

  1. 初期対応モデルはCellposeとMask R-CNN。
  2. 共通の学習流れとモデル固有設定を分離する。
  3. 一つの論理設定を一つの実験とする。
  4. 同一設定の再試行は実行試行として管理する。
  5. Optunaの各試行も通常実験と同じ保存形式を使用する。
  6. 学習用データによる交差検証（OOF）で評価し、正式評価用の検証用データセットとは分離する。
  7. 実際に使用したデータ識別ID一覧とフォールド割り当ては実験の設定ではなく、実行試行ごとに保存する。
  8. データ拡張設定は使用後に上書きせず新しい版を作る。
  9. 学習設定と推論設定を分離する。
  10. 学習中の主要自動評価指標は平均適合率（mAP）とする。
  11. 正式な比較候補作成・リリース・モデル振り分けはモデル比較・リリースモードで行う。

17. 交差検証（OOF）と最終学習

1実験は1つの学習設定で構成する。学習開始時に品質条件・画像分類で絞った学習用データだけをK分割し、検証用データセット（val版）は学習にも交差検証にも使わない。

  1. 既定K=5。画像分類で層別し、同じ取り込み元フォルダを同一フォールドにまとめ、data.seedで再現可能に割り当てる。実使用データ一覧にはデータ識別子とフォールド番号を保存する。
  2. 各フォールドを順に検証側として学習し、各評価エポックで全フォールドの検証予測を集約したOOF mAPとフォールド別mAPを保存する。早期終了はフォールドごとに適用し、OOF曲線は全フォールドが到達したエポックまでとする。
  3. OOF mAPが最大のエポックを共通の選択エポックとし、そのエポックのOOF予測を保存する。
  4. 同じ設定で学習用画像全体を選択エポック数まで再学習し、final.ptを作る。この段階は検証を行わずlossのみ記録する。

18. 学習キュー

複数の学習設定をキューへ保存し、先頭から1件ずつ順番に実行する。キュー項目も通常の実験として記録し、待機中は「待機」状態で実験一覧に表示する。順番は保存し、アプリを開き直しても維持する。

  1. 学習設定で検証済みの設定を末尾へ追加する。学習設定の「学習開始」も末尾への追加であり、学習していなければそのままキューの実行を始める（単独で学習する経路は持たない）。実験一覧の選択済み実験を新しい識別子で複製して追加する操作も用意する。
  2. 実行前にキュー表から設定を変更できる。各変更後に設定を検証し、エラー行は設定エラーとして残し、実行時には飛ばす。
  3. GPUは1台を前提とし、同時に実行する学習は常に1件とする。単発学習中にキュー実行を開始した場合は、単発学習の完了を待つ。
  4. 各学習は交差検証の各フォールド学習に続いて、選択エポックで学習用データ全体の最終学習を行う。成功、失敗、中断のいずれでも次の待機項目へ進む。
  5. 停止操作は現在の学習の完了後にキューを止める。即時中断は実験一覧の中断操作で行う。学習が終わった行（完了・失敗・中断）は自動でキュー表から外し、実験一覧の履歴には残す。復旧後などに残った行は「終了・中断した行を削除」で外せる。

状態は待機・実行中・完了・失敗・中断・設定エラーで表示し、進捗にはフォールド番号または最終学習エポックを含める。

18.1 同一実験の再試行

再試行（画面の操作名は「同じ設定でやり直す」）は同じ実験設定を用いる新しい実行試行であり、新しい実験識別子を作らない。過去試行の学習曲線、フォールド別履歴、OOF評価、選択エポック、途中保存モデル、実使用データとフォールド割り当てを保持する。実験一覧は最新試行を表示し、実行試行一覧から各試行のOOF mAP、選択エポック、結果、日時を確認できる。

学習が空いている場合は新しい試行を直ちに開始する。別の学習が実行中なら「再試行 N」としてキューに予約し、設定変更は許可しない。予約の削除は元実験の記録に影響しない。実行中の試行が終わると、キューの順序に従って同じ実験IDの次の試行を開始する。比較候補・リリースには作成元の試行番号とfinal.ptを記録し、後続試行の結果で参照値を変更しない。旧形式の実験は再試行せず、設定複製を案内する。

18.2 実験の削除

下書き・中断・失敗・完了の実験は、確認のうえ実験単位で削除できる。設定・全試行・途中保存モデル・OOF・ログとキュー行を削除し、データセット・事前学習済み重み・データ拡張プロファイルは残す。学習中・待機中の実験、比較候補（非採用を除く）やリリース済みモデルが参照する実験は削除できない。
