気泡 インスタンスセグメンテーションアプリ
データ準備モード仕様

本仕様は、気泡検出用インスタンスセグメンテーションモデルの開発に用いる 学習データを管理・整理・バージョニングするための「データ準備モード」を対象とする。

対象範囲：データ取り込み、メタデータ管理、作業中データセット、データセット版、 整合性確認、アーカイブ出力。

1. 基本方針

  • アノテーション作業自体は本アプリでは行わず、外部ソフトで作成したマスクを取り込む。
  • 一般ユーザーは主に推論機能を使用し、データ準備機能はアプリ開発者・管理者向けとする。
  • データ準備は一度で完了するとは限らないため、途中状態を継続保存できる構成とする。
  • 学習に使用すると判断した時点でのみ、確定版データセットとしてバージョンを発行する。
  • 確定済みデータセット版は変更不可とし、再現性を保証する。
  • 一度取り込んだ原画像・マスクは原則としてデータストアから削除しない。

2. 管理対象データ

2.1 原画像

モデル学習に使用する元画像。データストアへ登録後は恒久保存を基本とする。

2.2 正解ラベル画像

内部データとファイル形式の説明では従来どおり「マスク」と記す。利用者向け画面では、画像内の気泡位置を示す正解データを「正解ラベル画像」、その改訂を「正解ラベル版」と呼ぶ。修正時は過去データセットの再現性を保つため上書きせず、新しい正解ラベル版を作り、各版のハッシュ値を記録する。

2.3 メタデータ

詳細項目は業務要件に応じて定義するが、現時点では以下を主要候補とする。

項目用途
データ識別識別子画像・マスク・メタデータを一意に関連付けるキー
サンプル分類対象画像の分類・層別・学習条件管理
品質データ品質・アノテーション品質等の管理
「品質」と「データセットへの採用可否」は別概念として扱う。 品質が低いデータでも、ロバスト性確認等の目的で特定データセットに含める可能性があるためである。

3. メタデータ編集方式

メタデータは、アプリ内スプレッドシート形式と表計算ファイル入出力の両方に対応する。 内部データを正とし、表計算ファイルは編集用インターフェースとして扱う。

方式 主なメリット 主なデメリット
アプリ内表編集 入力値検証がしやすい。画像と同時確認できる。選択肢制御で表記揺れを防げる。 大量一括編集は表計算ファイルより操作性が劣る可能性がある。
表計算ファイル 出力 / 取込 コピー、フィルタ、一括編集に強い。利用者が慣れている。 列名変更、型崩れ、重複、行ずれ等の入力事故が起きやすい。

3.1 表計算ファイル連携ルール

  • 行番号ではなく、データ識別識別子をキーとして内部データと結合する。
  • 取込時は必須列、識別子重複、未知識別子、型、許容値、空欄等を整合性確認する。
  • 不整合がある場合は無理に取り込まず、エラー内容を表示して処理を中断する。
  • 表計算ファイルファイル自体を確定データセットの正本とはしない。

4. データ保管領域

アプリ内部では、一つの撮影対象を一つのサンプルとして扱い、原画像または複数の画像チャンネル、マスク各版、基本情報をデータ保管領域へ保存する。データセット版は、この領域内のデータを参照する形で構築する。

データ保管領域
├─ item_000001
│  ├─ images
│  │  ├─ channel_A
│  │  ├─ channel_B
│  │  └─ channel_C
│  ├─ masks
│  │  ├─ rev_001
│  │  └─ rev_002
│  └─ metadata
├─ item_000002
└─ ...

4.1 削除方針

  • 作業中データセットから除外しても、データ保管領域からは削除しない。
  • データセット版ごとに採用／除外を切り替えられるようにする。
  • 物理削除機能を設ける場合は、どのデータセット版からも参照されていないデータに限定し、管理者操作とする。

5. 作業中データセット

データ準備作業中は「作業中データセット」を編集する。 作業中データセットは途中保存可能であり、アプリ終了後も次回そのまま再開できる。

5.1 基本動作

  • 前回の確定データセット版を引き継いで作業を開始する。
  • 新規データを追加できる。
  • 既存データを除外できる。
  • メタデータを編集できる。
  • 使用する正解ラベル版を変更できる。
  • 途中保存のたびにデータセット版番号は増やさない。
データセット v003（確定済み） ↓ 引き継ぎ 作業中データセット + 新規画像追加 - 一部データ除外 + メタデータ変更 + 正解ラベル版の変更 ↓ データセット v004（新規確定版）

5.2 保存方式

手動保存ボタンを用意してもよいが、データ消失防止の観点から自動保存を基本とする。

6. データセット版管理

学習用データセットを確定する際は、基準とする検証用データセットとの重複をデータ識別識別子、ハッシュ値、必要に応じて試料識別情報で確認し、検証データの学習混入を防止する。

データセット版は共通の仕組みで管理し、用途として「学習用」と「検証用」を区別する。学習用データセットはモデル学習と学習内の交差検証に使用し、検証用データセットは学習には使用せず、モデル比較・正式リリース判断に使用する。

6.0 データセットの用途

6.1 バージョン発行タイミング

データセット版は「学習に使用する正式なデータセットとして確定する」と管理者が判断した時点で発行する。

作業中データセット ↓ 整合性確認 ↓ 内容確認 ↓ データセット版発行 ↓ データセット v001 / v002 / v003 ...

6.2 変更不可

一度確定したデータセット版は変更不可とする。 修正が必要な場合は作業中データセット側で変更し、新しいデータセット版を発行する。

モデル学習結果とデータセット版を一意に紐付けることで、 過去実験の再現性を維持する。

6.3 データセット版が保持する情報

  • 用途（学習用 / 検証用）
  • データセット版 識別子
  • 親データセット版
  • 作成日時
  • 採用データ一覧
  • 各データが参照する画像・マスク版
  • 確定時点のメタデータ
  • 変更コメント
  • 必要に応じて作成時のアプリバージョン

7. 整合性確認

データセット版発行前にデータそのものの整合性確認を実行する。これは、モデル学習時の交差検証分割や、モデル比較時の検証用データセットとは別概念である。

  • データ識別識別子の重複がないこと
  • 原画像が存在すること
  • 正解ラベル画像がそろっていること
  • 原画像と正解ラベル画像の対応が正しいこと
  • 必須メタデータが入力されていること
  • 原画像と正解ラベル画像の画像サイズが一致すること
  • ファイルハッシュが登録内容と一致すること
  • データセット版内で参照先が一意に確定していること

7.1 状態管理

データセットは少なくとも以下の状態を持つ。

WORKING
  ↓
VALIDATED
  ↓
RELEASED

確定済みになったデータセット版は以後変更不可とする。

8. ファイルハッシュ

同一ファイル名の画像やマスクが外部ソフトで上書きされた場合でも変更を検出できるよう、 SHA-256等のハッシュ値を記録する。

主な用途：

  • 同名ファイルの内容変更検出
  • データセット版再現性確認
  • 圧縮ファイルアーカイブの整合性確認
  • モデル実験とデータセットの追跡

9. データセットアーカイブ

確定済みデータセット版は、データ保管領域内の参照管理だけでなく、 原画像・マスクを含む完全スナップショットとして圧縮ファイル出力できるようにする。

圧縮ファイルファイルは別ストレージへ保管し、データ保管領域が失われた場合でも データセット版を完全復元できることを目標とする。

9.1 推奨アーカイブ構造

dataset_v004.zip
├─ images/
│  ├─ img_000001.png
│  ├─ img_000002.png
│  └─ ...
├─ masks/
│  ├─ mask_000001.png
│  ├─ mask_000002.png
│  └─ ...
├─ metadata.csv
├─ manifest.csv
└─ dataset_info.json

9.2 manifest.csv

再現性確認用の機械的情報を保持する。

項目例内容
item_id一意なデータ識別識別子
image_pathアーカイブ内の画像パス
image_sha256原画像ハッシュ
mask_pathアーカイブ内のマスクパス
mask_sha256マスクハッシュ
mask_版使用したマスク版
複数の画像チャンネルを持つ場合は、一覧ファイルにチャンネルごとの保存先とハッシュ値を記録する。

9.3 dataset_info.json

{
  "dataset_version": "v004",
  "parent_version": "v003",
  "created_at": "YYYY-MM-DD",
  "n_images": 537,
  "application_version": "x.y.z"
}

9.4 アーカイブ自体のハッシュ

圧縮ファイルファイルにもSHA-256を付与し、長期保存後も改変・破損を検証できるようにする。 

dataset_v004.zip
dataset_v004.zip.sha256

10. データセット確定とアーカイブ処理の分離

データセット版の確定と圧縮ファイルアーカイブ生成は、別ステータスとして管理する。 

Dataset status : RELEASED
Archive status : COMPLETED / FAILED / NOT_CREATED

アーカイブ出力に失敗してもデータセット版自体は確定状態を維持し、 後から再度アーカイブを生成できるようにする。

12. 全体フロー

外部アノテーションソフト ↓ 原画像・正解ラベル画像の取り込み ↓ データ保管領域へ恒久保存 ↓ 前回確定版データセットを引き継ぐ ↓ 作業中データセット ├─ データ追加 ├─ データ除外 ├─ メタデータ編集 └─ 正解ラベル版を選択 ↓ 整合性確認 ↓ データセット版確定 ↓ 確定済み / 変更不可 ↓ ┌───────────────────────┐ │ │ モデル学習へ使用 完全圧縮ファイル アーカイブ作成 │ │ 実験と紐付け 別ストレージへ保管 └───────────────────────┘

13. 現時点での設計原則まとめ

  1. 作業中データセットと確定データセットを分離する。
  2. 前回確定版を引き継いで次の作業中データセットを作成する。
  3. 途中保存ではデータセット版を増やさない。
  4. データセット版確定後は変更不可とする。
  5. データ保管領域上のデータは原則削除しない。
  6. 品質評価とデータセット採否を別概念として管理する。
  7. アノテーション修正は版として管理し、過去データセットを壊さない。
  8. メタデータ編集はアプリ内編集と表計算ファイル入出力を併用する。
  9. 確定データセットは完全圧縮ファイルとして外部ストレージへバックアップ可能とする。
  10. データセット確定とアーカイブ成功を別ステータスとして扱う。
  11. データセットは学習用と検証用を同じ版管理方式で扱い、用途を明示する。
  12. 検証用データセットは学習へ混入させない。
  13. 一つのサンプルに複数の画像チャンネルを関連付けられる構造とする。

確定学習版と検証版の組

学習版を確定する時点で RELEASED 状態の検証版を1つ選び、dataset_info.json の base_validation_version に保存する。確定後に参照先を変更しない。参照なし、空値、欠損、未確定、用途違いの検証版を参照する学習版は利用可能版一覧から除外し、理由を記録する。候補作成時はこの組を固定し、評価時は保存済みの組だけを軽く照合する。評価ごとの画像読込や重複検査は行わない。

学習用ダミーデータの生成時は --base-validation-version で検証版を指定でき、既定値は val_v000 とする。生成する画像 ID はデータセット版を含め、別版間の識別子衝突を避ける。
